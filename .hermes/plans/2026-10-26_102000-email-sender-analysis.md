# 邮件发送器 分析计划

> **目标：** 开发一个带 GUI 的本地桌面工具，替代手动在飞书网页/客户端里填收件人、选模板、粘贴正文的操作流程。

---

## 现状 vs 目标

| 环节 | 现在 | 目标 |
|---|---|---|
| 发件渠道 | 飞书（网页或客户端） | 自建 SMTP / API |
| 收件人 | 逐个手动输入 | 手动输入或快速粘贴批量地址 |
| 模板 | 靠记忆或手动复制 | 预设模板，一键选 |
| 节奏 | 每次手动操作 | 手动选择 + 确认后发送 |
| 界面 | 飞书 UI | 独立轻量桌面应用 |

---

## 核心设计决策

### 1. 语言 & 框架：Python + Tkinter（优先推荐）

| 选项 | 优点 | 缺点 |
|---|---|---|
| **Python + Tkinter** | 零依赖安装，打包为exe，纯文字模板够用 | 界面朴素 |
| Python + PyQt/PySide | 界面现代 | 体积大，打包复杂 |
| Electron（JS） | 界面好看 | Node依赖重 |
| Tauri（Rust+前端） | 体积小现代 | 开发成本高 |

**推荐：Python + Tkinter**，理由：
- 你的场景是纯文字+固定模板，不需要花哨 UI
- 一台 Windows 电脑，打包成单 exe 就能用
- Python 生态发邮件最简单（smtplib）

---

### 2. 发件通道：SMTP（推荐）vs 飞书 API

| 方式 | 说明 |
|---|---|
| **SMTP（首选）** | 直接连你的邮箱 SMTP 服务器发，不依赖飞书，独立运行 |
| 飞书 API | 需要 OAuth 授权，配置复杂，绑定飞书生态 |

**结论：用 SMTP**。你需要知道你的邮箱 SMTP 信息（下面会问）。

## 待确认问题（影响设计）

在你动手前，需要这几个信息：

1. **发件邮箱是什么？**（QQ/163/企业邮箱/Gmail？）—— 不同 SMTP 服务器地址和端口不一样
2. **你的云服务器要部署这个工具吗？** 还是只在本地 Windows 用？
3. **"两个都有"是指：**
   - A：既有群发通知（一封发给多人），也有一对一邮件
   - B：还有其他类型没说清楚
4. **有没有发件频率限制的需求？**（比如每小时最多发多少封，避免被当垃圾邮件）
